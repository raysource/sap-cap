4. 测试单元测试 + OData 集成测试⑦ 测试120 分验收脚本全绿

3. 受众与前置条件

适合谁

  • 后端/全栈工程师：要在 BTP 上做业务服务，但被 cockpit 的手顺和 CDS 的语法卡住

前置要求

  • 能读写 JSON / 命令行（会 cd、npm 即可）

  • 不需要 SAP 基础、不需要 ABAP 基础、不需要 Java 基础（Java 章节自带环境准备）
  • 一个能收邮件的地址（注册 BTP 试用用）

5. 课程交付的示范项目：图书受注管理

课程不是「讲完就算」——最后有一个完整、可运行的示范项目，同一个业务场景在三处出现： CDS 模型（共享）、Node.js 实现、Java 实现。项目源码随课程交付，位于 project-code/demo-node/ 与 project-code/demo-java/。

业务场景

  • Books 图书主数据（5 种，价格 2800–5200 JPY）
  • Customers 顾客（3 家：北京 / 上海 / 广州）
  • BookOrders 订单头（订单号 BO-1001…、状态 OPEN/SUBMITTED/CLOSED、合计）
  • BookOrderItems 订单明细（金额 = 单价 × 数量，由服务端计算）
  • OrderItemView 带主键的展开视图（可直接暴露为只读实体）

覆盖的技术点

  • 服务端编号生成 + 唯一性校验（409）
  • 派生字段计算（before CREATE/UPDATE）
  • 父表汇总回写（after CREATE/UPDATE/DELETE）
  • 绑定动作（bound action）状态迁移 + 业务校验（400/404/409）
  • 无绑定函数返回聚合结果（聚合视图没有主键，不能暴露为实体）
  • 草稿（@odata.draft.enabled）与 Fiori 编辑流程

五个层次的产物

层文件（示范项目内）怎么验证
模型db/schema.cds、db/data/*.csvnpm run deploy → 查 sqlite 表与行数

实现srv/book-order-service.js业务规则的正例/负例各测一次（见验收脚本）

9. 关于画面与数据的说明

三点必须讲清楚
  • 画面：BTP Cockpit / BAS / HANA / Fiori 的界面是本站用 SVG 重绘的（图注标「高保真重绘」）， 用于在没有 SAP 账号的情况下把界面结构讲清楚。它们不是实机截图，标签文字可能随版本/区域变化。
  • 终端输出：标注「本地实机运行」的内容是真实命令的输出（命令写在图注里），可以自己复现。
